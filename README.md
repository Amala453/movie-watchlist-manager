# ReelList - Movie Watchlist Manager

MERN stack movie watchlist application. The React frontend communicates with an Express/Mongoose API, and movie records are stored in MongoDB Atlas.

## Project structure
- `frontend/` React + Vite client
- `backend/` Express REST API + Mongoose models

## Run locally
1. Install Node.js LTS and create a MongoDB Atlas test database.
2. In `backend/.env`, set `MONGO_URI` to your test connection string and `CLIENT_URL` to `http://localhost:5173`.
3. In a terminal: `cd backend`, then `npm install`, then `npm run dev`.
4. In another terminal: `cd frontend`, then `npm install`, then `npm run dev`.
5. Open the Vite URL printed in the terminal (normally `http://localhost:5173`).
6. Set `VITE_API_URL=http://localhost:5000/api` in `frontend/.env` if needed, then restart Vite.

## API endpoints
- `GET /api/health` health check
- `GET /api/movies?status=&genre=&search=&page=` list/filter/search/paginate (6 per page)
- `GET /api/movies/watch-next` highest-priority To Watch movie (shortest runtime tie-break)
- `GET /api/movies/stats` dashboard statistics
- `POST /api/movies` add movie (code generated by backend)
- `PUT /api/movies/:id` edit title, genre, runtime, platform, priority (year/code are immutable)
- `PATCH /api/movies/:id/status` change status (rating required for Watched)
- `PATCH /api/movies/:id/rating` edit rating for Watched movies only
- `DELETE /api/movies/:id` delete unless status is Watching

Responses use `{ success, message, data }`. Duplicate title/year returns 409. Validation errors return 400 and missing resources return 404.

## Render deployment
- Backend: create a Render Web Service using root directory `backend`; build command `npm install`; start command `npm start`. Add `MONGO_URI` and `CLIENT_URL` environment variables in Render.
- Frontend: create a Render Static Site using root directory `frontend`; build command `npm install && npm run build`; publish directory `dist`. Set `VITE_API_URL` to `https://YOUR-BACKEND.onrender.com/api` and redeploy.
- Add only test/dummy credentials to any committed `.env` file. Never commit a real database password.
